快速排序（Quicksort）详解

快速排序是 Tony Hoare 在 1960 年提出的一种分治排序算法。它在平均情况下的时间复杂度是 O(n log n)，并且是原地排序（不需要额外的大块内存），因此在实际工程里比归并排序更常用。

一、核心思想

快速排序可以概括成三句话：

  1. 选基准（pivot）：从数组里挑一个元素作为分界点。
  2. 分区（partition）：把小于基准的放到左边，大于基准的放到右边，基准就位。
  3. 递归：对左右两段分别重复上面两步，直到每段只剩 0 或 1 个元素。
分治的关键不是"分"，而是"合"。快排之所以快，是因为它根本不需要"合"——分区完成时，元素已经在最终位置上了。

二、Lomuto 分区方案

最常见的实现是 Lomuto 方案：取最后一个元素做基准，用一个指针 i 维护"小于区"的右边界。

def quicksort(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo >= hi:
        return
    p = partition(a, lo, hi)
    quicksort(a, lo, p - 1)
    quicksort(a, p + 1, hi)

def partition(a, lo, hi):
    pivot = a[hi]
    i = lo
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    return i

三、Hoare 分区方案

Hoare 的原始方案用两个指针从两端向中间夹逼，交换逆序对。它的交换次数更少，在有很多重复元素的数组上表现更好。

int hoare_partition(int a[], int lo, int hi) {
    int pivot = a[(lo + hi) / 2];
    int i = lo - 1, j = hi + 1;
    while (1) {
        do { i++; } while (a[i] < pivot);
        do { j--; } while (a[j] > pivot);
        if (i >= j) return j;
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
}

五、关于最坏情况的几点提醒

  • 当输入已经完全有序时，固定取末元素做基准会退化成 O(n²)。
  • 常见的对策是随机化基准，或者取"首、中、尾"三者的中位数（median-of-three）。
  • 递归深度最坏可达 O(n)，所以工程实现通常先处理较短的一边，把递归深度压到 O(log n)，这叫尾递归优化。
  • 当子数组长度小于某个阈值（常见是 16）时，切换到插入排序反而更快，因为小数组上快排的函数调用开销盖过了算法优势。
  • 大量重复元素会让 Lomuto 分区退化成 O(n²)，此时应该用三路划分（Dutch national flag）。

六、三路划分（处理重复元素）

把数组分成 < pivot、== pivot、> pivot 三段，中间那段直接确定位置，不再递归：

def three_way(a, lo, hi):
    if lo >= hi:
        return
    pivot = a[lo]
    lt, i, gt = lo, lo, hi
    while i <= gt:
        if a[i] < pivot:
            a[lt], a[i] = a[i], a[lt]
            lt += 1; i += 1
        elif a[i] > pivot:
            a[i], a[gt] = a[gt], a[i]
            gt -= 1
        else:
            i += 1
    three_way(a, lo, lt - 1)
    three_way(a, gt + 1, hi)

七、稳定性与工程取舍

快速排序不稳定：相等的元素在分区时可能被换到别处。如果需要稳定，就得给元素附加原始下标做二级比较键，代价是额外空间和常数时间。

工程上的普遍做法是混合排序：introsort = 快排 + 堆排序 + 插入排序。递归深度超过 2·log n 时切换成堆排序，保证最坏情况也是 O(n log n)；小数组切插入排序。C++ 的 std::sort、Go 的 sort.Slice 都属于这一类。

如果你只需要记住一句话：快排的性能一半取决于分区策略，另一半取决于基准的选择。这两件事决定了它是在 O(n log n) 还是 O(n²) 上跑。

八、小结

  1. 分治 + 原地分区，平均 O(n log n)，常数因子小，是通用排序的首选。
  2. 最坏 O(n²)，靠随机化 / 三数取中 / introsort 规避。
  3. 不稳定；重复元素多时用三路划分。
